# Astel Reply Engine v9.1.1c — FROZEN IMPLEMENTATION SPEC

Status: FROZEN for implementation

## Objective
Add branch-isolated short-term memory and AI cost telemetry without changing the existing conversation-level 3-reply budget, v9.1.1a router semantics, or v9.1.1b branch identity semantics.

## Invariants
- `conversationKey = user + root` remains the safety/budget identity.
- `branchKey = root + branch head` is the semantic-memory identity.
- Graph + confirmed publish state are authoritative. Memory is derived context/cache only.
- Only real user comments and confirmed `PUBLISHED` bot replies may enter memory.
- `FAILED`, `RESERVED`, generated-only and `AMBIGUOUS` assistant content never enters memory.
- `PENDING_RELATIONSHIP` must not generate an AI reply; fail/hold until relationship is resolved.
- Redis/source-of-truth failure fails closed.
- Current comment language controls reply language; historical memory is context only.
- Existing source-comment idempotency remains authoritative.

## Memory
- Reconstruct memory from Conversation Graph for the exact `branchKey`.
- Exclude the current comment from historical memory and append it separately to the model request.
- Maximum 8 historical messages.
- Maximum estimated 1000 memory tokens by default; configurable between 800–1200 without code redesign.
- Walk parent chain backward from current comment's parent; keep only nodes in the same resolved branch; reverse into chronological order.
- Bot nodes are eligible only when `isBotGenerated=true`, `publishStatus=PUBLISHED`, and `text` is non-empty.
- User nodes are eligible when resolved and text is non-empty.
- Cache, if used, is disposable and never an independent truth source.

## Publish consistency
- `commitSuccess(reservation, publishedReplyId, publishedReplyText)` receives the exact confirmed text sent to Meta.
- A confirmed bot Graph node stores `text`, `publishStatus=PUBLISHED`, and `publishConfirmedAt`.
- Authoritative publish commit happens before Graph projection.
- Graph projection failure must never turn an already-published reply into a failed publish; it must be logged for reconciliation.
- Dry-run content must not be projected as a public bot Graph node.

## Same-branch concurrency
- Use a branch processing lease with owner token and TTL, not a long-lived blind mutex.
- Acquire before memory read/generation.
- Verify ownership immediately before external Meta publish.
- Release only if caller still owns the lease.
- Losing the lease before publish means no publish.
- External Meta HTTP cannot be made atomic with Redis; ambiguous publish semantics remain authoritative.

## AI context order
1. system/persona/hard rules
2. relevant KB
3. branch memory
4. current comment

Historical user content is untrusted conversation data and cannot override system/policy rules.

## Telemetry
For every actual model call emit structured `AI_USAGE` containing:
- traceId / reservationId
- sourceCommentId, conversationKey, branchKey, model
- systemTokensEstimated, kbTokensEstimated, memoryTokensEstimated, currentCommentTokensEstimated
- memoryMessages
- inputTokensActual, outputTokensActual, cachedInputTokensActual when returned by API
- estimatedCostUsd when configured pricing is available

AI usage is recorded even when publish later fails or becomes ambiguous. Safety skips before AI produce no AI usage event.

Raw token counts are primary. Cost is derived from a versioned/configurable model-pricing table so historical usage can be recalculated.

## Non-goals
No HUMAN_LOCKED, automatic takeover, Postgres migration, long-term summarization, CRM, DM engine, IG/FB, per-branch reply budget, or closing-policy redesign in this release.

## Acceptance
- exact-branch contextual continuation works;
- same-user sibling branches do not leak memory;
- cross-user memory does not leak;
- only confirmed bot replies enter memory;
- ambiguous/failed replies do not;
- memory is bounded by message count + token estimate;
- current language wins;
- pending relationships do not invoke AI;
- all old tests remain green;
- new v9.1.1c tests pass;
- live Threads test proves continuation + branch isolation.
